## What this is

MigrateLens (repo directory `landfall`) is a personalised Australian skilled-migration (189/190/491) information tool. The current phase is the paid report: a free points check whose result (points and three visa stamps) needs no email, and a personal PR report issued by the server, free for the Founding 100 (an emailed code) and then paid through Razorpay, built from real published SkillSelect data. The static frontend talks to separately deployed Supabase Edge Functions and Postgres (the report functions, feedback, and the PDF and email delivery job). It has no accounts. The checkout and forms require public configuration and a deployed backend; do not claim that payments, collection or delivery are live before the founder has verified them (the rehearsal checklist at the top of `docs/HANDOFF.md`; merging the paid report to `main` is going live, so it waits for that rehearsal). See `docs/OPERATIONS.md`. **Read `docs/STRATEGY.md` first.** It holds the founder's goals, decisions and approved roadmap, and it overrides older docs where they conflict. Working history lives in `.superpowers/`. `sdd/<plan>/progress.md` holds each plan's ledger: rulings, task outcomes and deferred issues. Briefs and reports sit beside it. `brainstorm/*/` holds the design mockups and `decisions.md`. Read the relevant ledger before continuing a plan. **Follow `docs/ENGINEERING.md`** for every code change: architecture, readability limits, styling, testing and the definition of done. Background direction is in `docs/PRODUCT.md`. The resume point and open QA list are in `docs/HANDOFF.md`. `docs/REPORT-COVERAGE.md` records which report sections are supported, limited or deferred.

Both dev and build use webpack on purpose. A stale Turbopack dev bundle once caused false regressions, so do not switch to Turbopack. Do final browser verification against the built `out/` static export, not the dev server. Node 22.12+ is required.

## Architecture

- **Static export only.** `next.config.ts` sets `output: "export"`, `trailingSlash: true` and `experimental.cssChunking: false` (the default merger put other routes' CSS on every page; see `docs/HANDOFF.md`). The root `not-found.tsx` loads on every route, so it imports nothing from other routes' components. Internal links therefore end in `/` (`/check/`, `/sample/`). Next.js server-only features (route handlers, server actions, dynamic rendering) will not work in this phase. Supabase Edge Functions run separately from this static export.
- **Pure domain layer in `src/lib/`.** Keep it separate from the UI and test it directly.
  - `migration.ts`: the `Profile` type, `calculatePoints(profile, asOf)` and `buildTimeline(profile, asOf)`. All dates are `YYYY-MM-DD` calendar strings, parsed and calculated in UTC so the host time zone never matters. Only `localToday()` reads the browser's local date. Every calculation takes an explicit `asOf`: the check flow uses `localToday()`, and the sample page pins `"2026-11-17"`.
  - `pool.ts`: SkillSelect counts. A published `"<20"` becomes the interval `{min: 0, max: 19}`, and all arithmetic is on intervals (`comparePool`, `formatInterval`). Never collapse a masked count to a single number.
  - `report-evidence.ts`: the report's evidence types (190/491 distributions, monthly 189 totals, invitation rounds), `netPoolChange` and `validateOccupationEvidence`. A `null` round cutoff means "not listed". It does not mean zero.
  - `data/`: the per-occupation dataset. `types.ts` and `guards.ts` define and check the records; pure accessors (`pool-position`, `invitations`, `cohorts`, `state-evidence`, `similar-profile`) answer report questions; `legacy.ts` adapts a core record to the shapes the current report reads (`toPoolOccupation`, `toOccupationEvidence`). `load-server.ts` reads files with `fs` and is for Server Components only. Files here and in `scripts/import/` use relative imports, not `@/`, because they run under tsx and vitest.
  - `scenarios.ts`: "what if" credential scenarios. These produce a modified `Profile` that goes back through `calculatePoints`.
- **Checked-in data.** The SkillSelect dataset (snapshot `skillselect-2026-10-31`, 493 occupations) is written only by the TypeScript importer in `scripts/import/`: raw history in `data/raw/<asAt>/` (and each round's current-round page in `data/raw/rounds/<date>.html`), and `src/data/manifest.json`, `occupation-index.json`, `rounds.json` (v2: totals, tie-break dates, state nominations; types in `src/lib/data/rounds-file.ts`) and `occupations/<code>.json` (core) plus `<code>.detail.json`. Read `docs/DATA.md` (the data dictionary) before using any of it; `scripts/README.md` covers the commands. `states.ts` holds hand-sourced summaries of the state/territory programs.
- **Loading data.** Server Components (pages) load what they render statically through `load-server.ts`. Client components may import only `occupation-index.json` (via `src/components/data/occupation-index.ts`) and `rounds-meta.json` (the skipped 189 rounds, via `src/components/data/rounds-meta.ts`) and `src/data/manifest.json` (about 1 KB, for the data month when an occupation has no core) and the state rule data (the 2026–27 rules, the four imported state lists and the federal occupation list, about 11 KB gzipped, via `src/components/data/state-rule-data.ts`, or the federal list alone, about 2.4 KB, via `federal-list.ts`; see "State rules" in `docs/DATA.md`), and fetch one occupation at a time with `useOccupationCore` (or `useOccupationDetail` for the detail file), from `/data/occupations/<code>.json` and `<code>.detail.json` (copied to `public/` before `dev` and `build`). Pass that hook a stable, module-level index array. While loading, show "Loading published data…", never a "not in snapshot" message.

## Product constraints

These come from the docs and past reviews:

- Do not invent data. That means no percentage chances, exact same-score rankings, testimonials, user counts or claims of live services. Pool comparisons count EOIs, not people. Since the 21 Nov 2026 founder decision, estimates (waits, pace, best route) are allowed when computed in code from published history and labelled as estimates; percentage chances stay banned and the AI never decides a label or number. You may show history-based counts (EOIs ahead of you, at your score, outcomes of similar EOIs) and historical waits, as defined in `docs/STRATEGY.md`.
- The free check sends nothing: the profile stays in the browser until the reader asks for the full report.
