## What this is

MigrateLens (repo directory `landfall`) is a personalised Australian skilled-migration (189/190/491) information tool. The current phase is the "useful first release": a free points check and report built from real published SkillSelect data. The static frontend now includes calculation-email capture and feedback backed by separately deployed Supabase Edge Functions and Postgres. It has no accounts, payments, email delivery or PDF worker. Submission forms require public configuration and a deployed backend; do not claim that production collection is active before it is verified. See `docs/OPERATIONS.md`. **Read `docs/STRATEGY.md` first.** It holds the founder's goals, decisions and approved roadmap, and it overrides older docs where they conflict. Working history lives in `.superpowers/`. `sdd/<plan>/progress.md` holds each plan's ledger: rulings, task outcomes and deferred issues. Briefs and reports sit beside it. `brainstorm/*/` holds the design mockups and `decisions.md`. Read the relevant ledger before continuing a plan. **Follow `docs/ENGINEERING.md`** for every code change: architecture, readability limits, styling, testing and the definition of done. Background direction is in `docs/PRODUCT.md`. The resume point and open QA list are in `docs/HANDOFF.md`. `docs/REPORT-COVERAGE.md` records which report sections are supported, limited or deferred.

Both dev and build use webpack on purpose. A stale Turbopack dev bundle once caused false regressions, so do not switch to Turbopack. Do final browser verification against the built `out/` static export, not the dev server. Node 22.12+ is required.

## Architecture

- **Static export only.** `next.config.ts` sets `output: "export"` and `trailingSlash: true`. Internal links therefore end in `/` (`/check/`, `/sample/`). Next.js server-only features (route handlers, server actions, dynamic rendering) will not work in this phase. Supabase Edge Functions run separately from this static export.
- **Pure domain layer in `src/lib/`.** Keep it separate from the UI and test it directly.
  - `migration.ts`: the `Profile` type, `calculatePoints(profile, asOf)` and `buildTimeline(profile, asOf)`. All dates are `YYYY-MM-DD` calendar strings, parsed and calculated in UTC so the host time zone never matters. Only `localToday()` reads the browser's local date. Every calculation takes an explicit `asOf`: the check flow uses `localToday()`, and the sample page pins `"2026-11-17"`.
  - `pool.ts`: SkillSelect counts. A published `"<20"` becomes the interval `{min: 0, max: 19}`, and all arithmetic is on intervals (`comparePool`, `formatInterval`). Never collapse a masked count to a single number.
  - `report-evidence.ts`: the report's evidence types (190/491 distributions, monthly 189 totals, invitation rounds), `netPoolChange` and `validateOccupationEvidence`. A `null` round cutoff means "not listed". It does not mean zero.
  - `data/`: the per-occupation dataset. `types.ts` and `guards.ts` define and check the records; pure accessors (`pool-position`, `invitations`, `cohorts`, `state-evidence`, `similar-profile`) answer report questions; `legacy.ts` adapts a core record to the shapes the current report reads (`toPoolOccupation`, `toOccupationEvidence`). `load-server.ts` reads files with `fs` and is for Server Components only. Files here and in `scripts/import/` use relative imports, not `@/`, because they run under tsx and vitest.
  - `scenarios.ts`: "what if" credential scenarios. These produce a modified `Profile` that goes back through `calculatePoints`.
- **Checked-in data.** The SkillSelect dataset (snapshot `skillselect-2026-10-31`, 493 occupations) is written only by the TypeScript importer in `scripts/import/`: raw history in `data/raw/<asAt>/`, and `src/data/manifest.json`, `occupation-index.json`, `rounds.json` and `occupations/<code>.json` (core) plus `<code>.detail.json`. Read `docs/DATA.md` (the data dictionary) before using any of it; `scripts/README.md` covers the commands. `states.ts` holds hand-sourced summaries of the state/territory programs.
- **Loading data.** Server Components (pages) load what they render statically through `load-server.ts`. Client components may import only `occupation-index.json` (via `src/components/data/occupation-index.ts`) and `rounds-meta.json` (the skipped 189 rounds, via `src/components/data/rounds-meta.ts`) and `src/data/manifest.json` (about 1 KB, for the data month when an occupation has no core) and the state rule data (the 2026–27 rules, the four imported state lists and the federal occupation list, about 11 KB gzipped, via `src/components/data/state-rule-data.ts`; see "State rules" in `docs/DATA.md`), and fetch one occupation at a time with `useOccupationCore` (or `useOccupationDetail` for the detail file), from `/data/occupations/<code>.json` and `<code>.detail.json` (copied to `public/` before `dev` and `build`). Pass that hook a stable, module-level index array. While loading, show "Loading published data…", never a "not in snapshot" message.
- **UI in `src/components/`.** `check-flow.tsx` is the four-step form, with validation and opt-in `localStorage` saving. `report.tsx` is the generated report, shared by `/check/` and `/sample/`. Since the 21 Nov 2026 redesign it is built from `buildOutlookView` (`src/lib/outlook/view.ts`) and the components in `src/components/report/`: `outlook-hero` (the big stamp and the "Our read" text from `our-read.tsx`), `visa-row` (three visa stamps), `route-section` (`route-line` on desktop, `route-list` on tablets and phones), `charts-section` (queue bar and squares, cut-off columns), `improve-section`, `evidence-section` (state panels, tables, the Sharpen questions, comparison and trend chart, closed by default on screen), `points-page`, `method-note` and `report-footer`. Stamps (`big-stamp`, `visa-stamp`, `shift-stamps`) use the report font Archivo, not the stencil face in the spec (ruling R22), and never animate. Components only render pure view-models; copy follows `src/lib/report/copy.ts` (`BANNED_COPY`) and `src/lib/outlook/phrases.ts`.
- **Outlook logic, `src/lib/outlook/`.** Pure, relative imports. `labels.ts` (the nine labels, their rank and display names), `label-189.ts` and `label-state.ts` (code decides every label), `evaluate-profile.ts`, `stamp.ts` and `stamp-geometry.ts`, `wait.ts` (pace and wait estimates), `headline.ts`, `improve.ts` and `losses.ts` (what would change the label, dated losses), `route.ts`, `route-deadlines.ts` and `route-geometry.ts`, `charts.ts` and `queue-view.ts`, `facts.ts`, `read-template.ts` and `read-contract.ts` (the AI "Our read" contract: `ReportFacts`, `checkRead`; dependency-free because Deno imports it), `print-page.ts`, `examples.ts` (the four /sample/ profiles) and `view.ts`/`visa-cards.ts` (the combined view-model). Read `docs/REPORT-COVERAGE.md` for what the report now contains.
- **Print layout.** The print report is a separate tree (`print-report.tsx`, `print-appendix.tsx`) rendered only for print; the screen tree is hidden then. Every section must print and each sample tab stays within 5 pages. `@page` margins are set at the top level (14/14/18 mm).
- **Sample page.** `/sample/` shows four example reports as tabs (Strong, In the middle, 189 closed, Nothing suits) from `src/lib/outlook/examples.ts`, built at build time by `src/app/sample/page.tsx` and `report/sample-tabs.tsx`.
- **AI "Our read".** The `write-read` Supabase Function (`supabase/functions/write-read/`, shared code in `_shared/read.ts`) words the computed `ReportFacts` in 60 to 90 words. Server env vars: `ANTHROPIC_API_KEY`, `READ_MODEL` (default `claude-opus-5-5`), `READ_ENABLED` (default false), `READ_MAX_OUTPUT_TOKENS` and `READ_TOKEN_SECRET` (HMAC for read tokens). Frontend switch: `NEXT_PUBLIC_READ_ENABLED` (default off). Both switches are off, so reports show the template read. The hook `report/use-our-read.ts` accepts a reply only if `checkRead` passes within 6 seconds. See `docs/OPERATIONS-BACKEND.md`.
- **Brand.** The MigrateLens tokens (ink, newsprint, card, saffron marks, slate links, the five status pairs, focus rings) are CSS custom properties on `:root` in `src/app/globals.css`, mirrored by `src/lib/brand/palette.ts`; its tests check contrast and that the two stay in sync. Saffron is for marks and lines, never text. Type is Newsreader 600 (headlines, big numbers) and Inter 400/500/600, both self-hosted through `@fontsource` (no Google Fonts requests). The logo (C1: ring, three bars) is `src/components/brand/` (`mark-geometry.ts`, `logo.tsx`, `brand.tsx`); the favicon is `src/app/icon.svg`; `public/og.png` comes from `npm run og:image`. `src/app/no-old-name.test.ts` keeps the old name out of the source; the legacy storage key in `src/lib/profile-storage.ts` is allowlisted because it is migrated and cleared.
- **Occupation pages.** `/occupations/` (searchable index) and `/occupations/<slug>/` (one statically generated page for each of the 479 occupations with published data (14 of the 493 have none); the slug is the name plus the code, from `src/lib/occupation-page/slug.ts`). Pure view-models, questions, related occupations, metadata and JSON-LD are in `src/lib/occupation-page/`; components are in `src/components/occupation/`. The pages read the core and detail files at build through `load-server.ts`. `src/lib/site.ts` holds `SITE_URL` and the launch switch `SITE_INDEXABLE` (false: every page is `noindex` and `robots.txt` disallows all; do not flip it before the founder launches). `src/app/sitemap.ts` lists only occupations that have data and at least one count that is not "<20"; `src/app/robots.ts` follows the switch. The header has an "Occupations" link and the homepage try-it links to the chosen occupation's page.
- **Homepage.** `src/app/page.tsx` composes `src/components/home/` (two-door entry, try-it, three questions, FAQ, hero demo). Pure view-models and copy are in `src/lib/home/` (`home-copy.ts`, `try-it.ts`, `demo-content.ts`); the FAQ is `components/home/home-faq.ts`. `buildSampleView` (`components/home/sample-view.ts`) builds the sample report view from the constants in `src/lib/sample.ts`. The hero demo is a Stageshow animation (the kit is vendored in `src/components/stageshow-kit/`, with a scoped eslint override and excluded from the 12px floor test; the skill is in `.agents/skills/stageshow`). Rehearsal steps for demo changes: `src/components/home/REHEARSAL.md`.
- `.openai/hosting.json` identifies the private preview hosting project. Preserve it, and never put credentials there.

## Product constraints

These come from the docs and past reviews:

- Do not invent data. That means no percentage chances, exact same-score rankings, testimonials, user counts or claims of live services. Pool comparisons count EOIs, not people. Since the 21 Nov 2026 founder decision, estimates (waits, pace, best route) are allowed when computed in code from published history and labelled as estimates; percentage chances stay banned and the AI never decides a label or number. You may show history-based counts (EOIs ahead of you, at your score, outcomes of similar EOIs) and historical waits, as defined in `docs/STRATEGY.md`.
- The full personal Profile stays in the browser. The founder-approved email gate sends only email and the allowlisted calculation summary (occupation, age band, onshore/offshore, points, snapshot) to Supabase after disclosure. Feedback sends only its selected fields. Never put personal data in the URL; the only allowed query parameter is a pre-selected `?occupation=` code. Save the full profile locally only after explicit opt-in; exclude email and provide a way to clear it.
- `eligible` in `PointsResult` covers only age, English and assessment validity. It never means full visa eligibility. State summaries must keep federal points separate from state scoring.
- Every report section prints in the PDF; interactive controls and the detailed views inside "See the evidence" are screen only.
- Every animation must respect reduced motion.
- `docs/original-references/` holds the original SPEC and HTML mockups. They must stay byte-for-byte unchanged. Treat them as historical context only; they are not current requirements.

## Submission backend

`src/lib/submissions/contract.ts` is the dependency-free contract shared with Deno. `summary.ts` projects an allowlist from the full Profile. Browser transport and Turnstile are in `src/components/submissions/`; email never enters Profile/localStorage/report printing. Supabase migrations and public write Functions are in `supabase/`; public table/RPC access is denied. `npm run backend:check`, `backend:test` and `backend:test:sql` verify the backend separately from Next.js. Configure/deploy per `docs/OPERATIONS.md` and `docs/OPERATIONS-BACKEND.md`. Keep the full Supabase runtime outside the frontend TypeScript check.
